CNN3 architecture

Three convolutional layers. The notebook does not count BatchNorm, ReLU, pooling, dropout, or the classifier as convolutional depth.

Input ↓ Conv 32 → BatchNorm → ReLU → Pool ↓ Conv 64 → BatchNorm → ReLU → Pool ↓ Conv 128 → BatchNorm → ReLU ↓ Global Average Pooling ↓ Dropout(0.30) ↓ Dense / Linear classifier

CNN5 architecture

Adds two more convolutional transformations and one extra pooling stage.

Input ↓ Conv 32 → BatchNorm → ReLU → Pool ↓ Conv 64 → BatchNorm → ReLU → Pool ↓ Conv 128 → BatchNorm → ReLU ↓ Conv 128 → BatchNorm → ReLU → Pool ↓ Conv 160 → BatchNorm → ReLU ↓ Global Average Pooling ↓ Dropout(0.30) ↓ Dense / Linear classifier

The data flow

Raw data ↓ Audit + validation ↓ Cleaning / normalization ↓ Train / validation / test split ↓ CNN3 or CNN5 ↓ Loss + backpropagation + optimizer ↓ Best validation checkpoint ↓ Test evaluation ↓ Metrics + confusion + confidence + calibration

Why the three datasets?

Fashion-MNIST shows a compact grayscale image task. CIFAR-100 stresses the same CNN family with RGB input and 100 classes. Diabetes is tabular, so the notebook uses Conv1D as an assignment-driven adaptation after missing-value handling, categorical encoding, scaling, patient-group splitting, and class weighting.

The dashboard intentionally preserves these distinctions instead of treating the 12 runs as one universal leaderboard.

TensorFlow/Keras

compile() and fit() provide a higher-level training API. The dashboard can load the saved .keras checkpoints for inference.

PyTorch

nn.Module, forward(), backward(), and optimizer.step() expose more of the training loop. The dashboard loads the saved .pth state dictionaries.

Evaluation

Accuracy is shown together with macro F1, weighted F1, log loss, ECE, parameter count, and training time so the demo follows the notebook's broader evidence model.
